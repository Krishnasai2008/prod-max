# How My Notes works (technical overview)

A private study-notes website. You write notes in Markdown, a static site generator turns them into HTML, and
Cloudflare Pages hosts the result behind a login. Study features (progress, to-do, timer, backup) are small
plain-JS scripts added on top of the theme. The repo has no Node build, no framework and no database apart from
one Cloudflare KV key per login.

This file sits at the repo root, outside `docs/`, so it is not published on the site.

---

## 1. Stack at a glance

| Layer | What | Where |
|---|---|---|
| Content | ~1,060 Markdown notes in folders, one top-level folder per subject | `docs/**.md` |
| Site generator | [Zensical](https://zensical.org) (the successor to MkDocs Material). It reads `mkdocs.yml` and uses the Material theme | `mkdocs.yml` |
| Build-time scripts | Python 3, standard library only. They rewrite Markdown before the build | `fix_links.py`, `tidy_markdown.py`, `make_indexes.py` |
| Search | [Pagefind](https://pagefind.app), which indexes the built HTML. The theme's own search is switched off | `pagefind.yml`, `docs/javascripts/search.js` |
| Math | `pymdownx.arithmatex` (generic mode), plus MathJax 3 loaded from jsDelivr only on pages with math | `docs/javascripts/mathjax.js` |
| Front-end features | Plain JS (no bundler, no modules), loaded through `extra_javascript` | `docs/javascripts/*.js` |
| Styling | One stylesheet. It defines colour tokens and overrides the theme | `docs/stylesheets/extra.css` |
| Hosting | Cloudflare Pages (free plan). Build command `bash build.sh`, output folder `site` | `build.sh` |
| Server code | One Cloudflare Pages Function (middleware) in front of every request: Basic auth, `/api/backup`, `/api/pm`, `/api/pm-inbox` and `/api/versus` | `functions/_middleware.js` |
| Tests | `node --test tests/` (middleware, page scripts, stats page) and `python -m unittest discover -s tests` (`make_indexes.py`) | `tests/` |
| Storage | The browser's `localStorage` (keys start with `study.`), mirrored to Cloudflare KV (`BACKUP` binding) | `backup.js`, `_middleware.js` |

Live URL: whatever you set as `site_url` in `mkdocs.yml`.

## 2. Repository layout

```
notes-site/
├── mkdocs.yml            # site config: theme, Markdown extensions, plugins, which JS/CSS to load
├── build.sh              # the Cloudflare Pages build (see §4)
├── pagefind.yml          # what Pagefind indexes
├── fix_links.py          # build step 1: repair links to notes that were moved
├── tidy_markdown.py      # build step 2: fix Markdown that renders badly (lists, $ math, "Added" dates)
├── make_indexes.py       # build step 3: generate every folder's index.md and the home page
├── functions/
│   └── _middleware.js    # Cloudflare Pages Function: login + /api/backup + /api/pm + /api/pm-inbox + /api/versus
├── tests/                # node --test tests/ and python -m unittest discover -s tests (never inside functions/)
├── docs/                 # everything here becomes the site
│   ├── index.md          # home page (GENERATED by make_indexes.py)
│   ├── <subject>/        # e.g. example/, operating-systems/ ...
│   │   ├── .nav.yml      # optional: folder title / sidebar order (awesome-nav)
│   │   ├── index.md      # GENERATED overview page, unless hand-written (see §4.3)
│   │   └── **/*.md       # the notes
│   ├── stats.md          # the stats page (/stats/): a mount point for pmstats.js, not a note
│   ├── javascripts/      # mathjax.js, search.js, backup.js, study.js, today.js, pmstats.js, pmhome.js, pmversus.js
│   └── stylesheets/extra.css
└── site/                 # build output (git-ignored)
```

A subject is the first path segment. The URL `/example/exam-prep/x/` belongs to subject `example`. The time tracker and
the home-page cards both rely on this. `stats` is reserved: `/stats/` is the stats page, not a subject
(`PAGES` in `today.js` and `make_indexes.py`), so the clock never counts it and it is not listed as a note.

## 3. Content model

- **A note** is any `.md` file under `docs/`. Its title is the first `# ` heading. Its URL is the path with
  `.md` replaced by `/` (`docs/example/getting-started.md` becomes `/example/getting-started/`).
- **Optional "Added" date:** a line `_Added: 2026-10-24_` in a note becomes a date label, and the note can then
  appear under "Recently added" on the home page.
- **Folder titles** come from `title:` in that folder's `.nav.yml`. Without one, the folder name is prettified
  (dashes become spaces and the first letter is capitalised).
- **Front matter** is optional (`hide: [toc]`, `tags: [...]`).
- **Math** is written the way VS Code's preview accepts it: `$inline$` and `$$display$$`. `tidy_markdown.py`
  makes it valid for Python-Markdown at build time (§4.2).
- **Practice mode** depends on how a note writes its questions. In a note with Q1/Q2-style questions (a `### Q3`
  heading or a bold `**Q3.**` paragraph), paragraphs starting with bold **Answer**, **Solution** or **Model answer**
  are hidden behind "Show answer". Test pages can instead pull answers from a matching key page:
  `x-test/` → `x-key/`, `x-quiz/` → `x-quiz-answers/`, `x-qns/` → `x-ans/`, `exam-qns-N/` → `exam-ans-key-N/`.

## 4. Build pipeline (`build.sh`, runs on Cloudflare)

```bash
pip install zensical "pagefind[extended]"
python fix_links.py        # 1
python tidy_markdown.py    # 2
python make_indexes.py     # 3
zensical build --clean     # 4  -> site/
rm -f site/search.json     # theme still writes its 28 MB index even with search disabled
python -m pagefind         # 5  -> site/pagefind/
find site -type f -size +25M -print -delete   # Cloudflare Pages rejects files > 25 MiB
```

Steps 1 to 3 **edit the Markdown in place**. On Cloudflare that edits a throwaway checkout, which is harmless.
Locally they would change your notes, so run them on a copy if you want to preview the result.

### 4.1 `fix_links.py`
Rewrites a relative link to an `.md` file that no longer exists. It points the link at wherever a note with the
same file name now lives, and only when exactly one such note exists. Index pages are matched by folder name.
Links inside code are left alone. `--check` only reports.

### 4.2 `tidy_markdown.py`
Works line by line and skips fenced code, inline code, front matter and the inside of `$$` blocks.
1. Adds a blank line before a list that is glued to the paragraph above it.
2. `_Added: YYYY-MM-DD_` → `Added YYYY-MM-DD` + `{ .added }`, which becomes a styled label.
3. Money such as `($26) ... ($28)` gets its `$` escaped, so the two signs don't pair up into a formula. This is
   a heuristic.
4. `$$` display math:
   - adds blank lines around a `$$` block
   - moves a `$$` block indented by 2 or 3 spaces to a multiple of 4
   - turns `$$x$$` in the middle of a sentence into `$\displaystyle x$`
   - in table rows, turns `|` inside `$…$` into `\vert{}`

It has assert-based self-checks that run on import (`python -c "import tidy_markdown"`).

### 4.3 `make_indexes.py`
- **Writes an `index.md`** for every folder that contains notes, and for `docs/` itself (the home page).
- **Leaves some folders alone:** a hand-written `index.md` (one without the `MARK` comment), and folders that
  have a `README.md`.
- **A folder with no notes of its own and a single subfolder** ("wrapper") lists that subfolder's contents.
- **Subject cards** take their icons from the `ICONS` dict.

What each page contains:
- **Home page (`docs/index.md`)**, from top to bottom:
  - the counts line
  - `<div class="study-continue" hidden>`
  - `<div class="study-today">`
  - `<div class="study-plan">` (pm's Planner box, `pmhome.js`), followed by the Versus box `pmversus.js` adds when there is versus data
  - the subject cards
  - `<div class="study-stats">`
  - the "Recently added" fold-out (the 6 newest notes that have an Added date)
- **Folder page:** the title, a note count, `<div class="study-progress" data-total="N">`, section cards and
  note cards.

The empty `div`s are **mount points** that the JS fills in (§6).

### 4.4 Zensical config (`mkdocs.yml`) highlights
- `navigation.instant`: page changes are swapped in by XHR without a full reload. **Every script must re-run
  its page logic on the theme's `document$` observable** (§6.1).
- `navigation.prune`: each page ships only its own part of the sidebar, which keeps 1,000+ pages fast.
- Two palettes follow the device's light/dark setting, with a toggle in the header: `default` is light and
  `slate` is dark.
- Markdown extensions: admonition, details, superfences (mermaid), tabbed, highlight, tasklist, keys, emoji,
  arithmatex, footnotes, `attr_list`, `md_in_html`.
- No `nav:` key: the sidebar comes from the folder tree, refined by `.nav.yml` files (awesome-nav plugin).

### 4.5 Pagefind (`pagefind.yml`)
Pagefind indexes only `article.md-content__inner` (each note's text) and excludes `.headerlink` and
`.study-meta`. The index is split into small chunks under `site/pagefind/`, about 1,450 files, none over 1 MB.
A search downloads only the chunks it needs, about 0.3 MB.

## 5. Server side (`functions/_middleware.js`)

It runs in front of **every** request, for static files too.

1. **Login (HTTP Basic auth).**
   - Credentials come from Cloudflare env vars `SITE_USER` + `SITE_PASSWORD`, and optionally `SITE_USER_2` +
     `SITE_PASSWORD_2`, `_3`, and so on.
   - No login configured → 503. Wrong or missing credentials → 401 with `WWW-Authenticate`.
   - The matched login's user name identifies that person for the backup.
   - Optional scoreboard-only logins: `VERSUS_USER` + `VERSUS_PASSWORD`, and `VERSUS_USER_2` +
     `VERSUS_PASSWORD_2`, `_3`, and so on. They are checked only on `/api/versus`; anywhere else they get
     the 401. A `VERSUS_USER` with the same name as a `SITE_USER` is ignored, and so is a second one with
     a name already taken.
2. **`/api/backup`**: one JSON blob per login in the KV namespace bound as **`BACKUP`**, under the key
   `backup:<user>`.
   - `GET` → the stored JSON, or `null` (`Cache-Control: no-store`).
   - `PUT` with a JSON object body (max 5 MB) → `204`. A body that isn't a JSON object → 400. Too large → 413.
   - Any other method → 405. `BACKUP` not bound → 503.
3. **`/api/pm`**: the same GET/PUT JSON-object store under the key `pm:<user>` (max 1 MB), same KV namespace.
   `pm stats --push` (the `pm` planner on the laptop) writes it and `pmstats.js` reads it. It can never touch
   `backup:<user>`. All the routes share `store(request, env, key, max)`.
4. **`/api/pm-inbox`**: the same store under `pm-inbox:<user>` (max 100,000 characters). The home page's
   Planner box (`pmhome.js`) writes it: tasks and time to send to the laptop, as `{"items": [...]}`. The laptop
   (`pm inbox` and the `pm watch` daemon, every 5 minutes) only reads it and acknowledges entries inside its
   own push (`inbox_done` in `pm:<user>`). Each key has one writer: the site writes `pm-inbox:`, the laptop
   `pm:`, the browser's backup `backup:`.
5. **`/api/versus`**: the study scoreboard (`pm versus`). It is the one route that comes before the
   site-login check, because the scoreboard-only logins (step 1) open it too. Every player is a site login
   or a scoreboard login.
   - `PUT` → the same store under `versus:<login>` (max 100,000 characters): a player's laptop writes only
     its own card (numbers per day). Each `versus:` key has one writer, that login's `pm`.
   - `GET` → `{"you": "<login>", "cards": {"<player>": <card>, ...}}`, every player's stored card (a
     stored value that isn't JSON is left out). Each `pm` checks the cards and scores the days itself.
   - `BACKUP` not bound → 503. A scoreboard login gets nothing else: no notes, no backup, no stats.
6. Everything else → `next()`, which serves the static file from `site/`.

KV keys, all in `BACKUP`: `backup:<user>` (the browser), `pm:<user>` (the laptop's push), `pm-inbox:<user>`
(the site's Planner box), `versus:<login>` (only that login's laptop).

Cloudflare settings this needs:
- Settings > Variables and Secrets: the `SITE_USER*` / `SITE_PASSWORD*` variables, for Production, and
  optionally `VERSUS_USER*` / `VERSUS_PASSWORD*` for friends who only play the scoreboard. Redeploy after
  adding variables.
- Settings > Bindings: a KV namespace bound as `BACKUP`.

## 6. Front end

### 6.1 Load order and lifecycle
All scripts are classic `<script>` tags in this order (`extra_javascript`). They share globals, so the order
matters:

| # | File | Role | Depends on |
|---|---|---|---|
| 1 | `mathjax.js` | Sets `window.MathJax` config, loads MathJax only if the page has `.arithmatex`, re-typesets after instant nav. Defines global `renderMath()` | — |
| 2 | `search.js` | Header **Search** button + `/` and Ctrl/Cmd+K. Lazily loads `pagefind/pagefind-ui.{js,css}` into a `<dialog class="study-search">` | Pagefind output |
| 3 | `backup.js` | Restores and pushes `localStorage` to `/api/backup` | Must run **before** anything writes `study.*` |
| 4 | `study.js` | Done ticks, progress bars, continue-reading, reading time, Focus mode, keyboard shortcuts, practice mode. Defines globals `load`, `save`, `doneSet`, `bar` | `search.js` (anchors the Focus button next to `.study-search-btn`) |
| 5 | `today.js` | To-do list, study clock and Pomodoro, stats and heatmap, "+ Today" button. Defines `heatCells(msOf, now)` and `streakOf(msOf, now)` | `study.js` globals |
| 6 | `pmstats.js` | The stats page: fetches `/api/pm` and draws it next to `study.time` (a day = the larger of the two clocks, never the sum). Defines `txt`, `pct`, `mins`, `hint`, `days` | `study.js` + `today.js` globals |
| 7 | `pmhome.js` | The home page's Planner box: fetches `/api/pm` (today's plan, reviews due with links to their notes) and sends tasks and time to `/api/pm-inbox`. It ends with a plain link to the laptop's `pm ui` (`http://127.0.0.1:8321/`, hidden on touch screens); the site never fetches from it. No pm data → the box is removed. Its top-level names start with `plan` or `pmHome` | `study.js` + `today.js` + `pmstats.js` globals |
| 8 | `pmversus.js` | The home page's Versus box, a study scoreboard against friends, right under the Planner box. It reads the optional `versus` key of the `/api/pm` object `pmhome.js` already fetched (`pmHomePage` calls `versusMount(box, pm)`), so it makes no request of its own; a missing or malformed `versus` (old pushes) draws nothing. Every name and label goes through `esc`, numbers through `Number`. Its top-level names start with `versus` | `today.js` + `pmstats.js` + `pmhome.js` globals |

**The page hook pattern used everywhere.** The header persists across instant navigation, so header widgets are
created once, guarded by an "already exists" check. Page widgets are rebuilt on every `document$` emission.

```js
if (typeof document$ !== "undefined") document$.subscribe(pageFn);  // fires on first load AND after each instant nav
else document.addEventListener("DOMContentLoaded", pageFn);
```

### 6.3 Browser storage schema (`localStorage`, JSON values)

| Key | Shape | Written by | Backed up |
|---|---|---|---|
| `study.done` | `string[]` of note paths, e.g. `"/example/getting-started/"` | study.js | ✔ |
| `study.last` | `{path, title, where}`: last note opened | study.js | ✔ |
| `study.focus` | `boolean` | study.js | ✔ |
| `study.todo` | `{day:"YYYY-MM-DD", items:[{id, text, done, href?, where?}]}`. On a new day, ticked items drop and unticked ones carry over | today.js | ✔ |
| `study.time` | `{"YYYY-MM-DD": {"<subject slug>": ms, "other": ms}}` (local dates) | today.js | ✔ |
| `study.subjects` | `{"<slug>": "Display name"}` | today.js | ✔ |
| `study.open` | `{"today": bool, "stats": bool, "plan": bool, "versus": bool}`: fold-out state | today.js, pmhome.js, pmversus.js | ✔ |
| `study.clock` | `{mode: "auto"\|"watch"\|"pomo25"\|"pomo50", start: ms}` | today.js | ✘ live state |
| `study.tick` | `ms`: last time any tab counted (stops two tabs counting the same time) | today.js | ✘ |
| `study.active` | `ms`: last user activity, shared across tabs | today.js | ✘ |
| `study.pushed` | `{h: hash, at: ms}`: last successful backup | backup.js | ✘ |
| `study.pminbox` | `[{id, at, op, ...}]`: entries this browser sent to `/api/pm-inbox` that the laptop hasn't acknowledged (failures stay until dismissed) | pmhome.js | ✘ a queue: restoring it would resend entries |

`sessionStorage["study.bells"]` marks which tab plays the Pomodoro chimes.

### 6.4 Backup and restore (`backup.js`)
- **On load, before any other script writes:** it notes whether the browser is empty, meaning none of
  `study.done`, `study.time`, `study.todo` or `study.last` exists.
- **Restore:** `GET /api/backup`. If the browser was empty and the backup has data, it writes every `study.*` key
  back and reloads the page.
- **Push:** every 30 s, and on `pagehide`, it `PUT`s all backed-up keys.
  - It skips the push if nothing changed (djb2 hash), and pushes at most once per 2 min across tabs. KV's free
    plan allows 1,000 writes a day.
  - It never pushes before a successful GET.
  - It never pushes data that has none of the core keys, so an empty browser can't overwrite a good backup.
  - It uses `keepalive` when the body is under 60 KB.
- It also calls `navigator.storage.persist()`.

### 6.5 Study clock (`today.js`)
- **Tick:** a 1 s `setInterval`, in every tab.
- **Auto mode** counts only when all of these hold:
  - the tab is visible
  - there was activity in the last 5 min
  - the page is inside a subject
- **Stopwatch** counts all the time.
- **Pomodoro 25/5 and 50/10** count the study phase only. The phase is computed from `start`, so it survives
  reloads. Chimes are scheduled on a Web Audio clock up to 4 h ahead.
- **Credited time** is `now - study.tick`, capped at 1 s in Auto and 90 s in other modes. The cap keeps a
  sleeping computer from adding time.
- **A forgotten stopwatch or Pomodoro** drops back to Auto after 3 h with no activity.
- **Day levels:** ≥ 2 h `green`, ≥ 4 h `orange`, ≥ 6 h `red`, and ≥ 1 min `some`. 2 h+ days build the streak.
  Levels are exposed as `[data-level]` and coloured with `--c-lv-*`.

### 6.6 Keyboard shortcuts
`/` or Ctrl+K search · `Z` focus · `D` mark done · `T` add to today · `← →` previous/next note · `?` help.
Shortcuts are ignored while typing in inputs or contenteditable elements, and when Ctrl, Cmd or Alt is held.

### 6.7 Styling (`extra.css`)
- **Colour tokens** are set per scheme on `[data-md-color-scheme="default"|"slate"]`:
  `--c-bg`, `--c-surface`, `--c-border`, `--c-text`, `--c-muted`, `--c-accent`.
  Material's `--md-*` variables are mapped onto them.
- **Day-level colours:** `--c-lv-green`, `--c-lv-orange`, `--c-lv-red`.
- **Fonts:** Inter for text, JetBrains Mono for code, Source Serif 4 for headings.
- **Custom elements** use the `study-` prefix.

## 8. Integrating with another project

**Ways to reuse each part**

| You want to… | Do this |
|---|---|
| Embed or link notes | Notes are static pages at stable URLs (`/<subject>/<path>/`). Every request needs Basic auth, so a browser asks for the login first. Another server needs an `Authorization: Basic …` header |
| Read the content directly | Use the Markdown in `docs/` (raw). Or build and read `site/**/index.html`, with content in `article.md-content__inner` |
| Search from another app | Load `/pagefind/pagefind.js` as an ES module: `const pf = await import("/pagefind/pagefind.js"); const r = await pf.search("query"); await r.results[0].data()` returns `{url, meta.title, excerpt, sub_results}`. It must be served from the same origin, or Pagefind's `bundlePath` set to a reachable URL |
| Show data from another app | Do what `pm` does: `PUT` a JSON object to a new route like `/api/pm` (its own KV key), and draw it from a page script. Never write into `/api/backup` |
| Send something to the laptop | Do what the Planner box does: append an entry with a unique `id` to `/api/pm-inbox` (`GET` it, merge your entries in by id, `PUT` it back), and read the laptop's answer from `inbox_done` in `/api/pm`. Never write `pm:<user>` from the site |
| Read or write study progress | `GET`/`PUT /api/backup` with the same Basic auth. It returns the §6.3 keys as a flat JSON object of **strings**, each holding the JSON value. Example: `{"study.done": "[\"/example/x/\"]", "study.time": "{...}"}`. A `PUT` replaces the whole blob, so read first, change it, then write it back |
| Add a new feature script | Add it to `extra_javascript` after `study.js`, use `load()`/`save()` with a new `study.<name>` key (it is backed up automatically unless added to `SKIP` in `backup.js`), and hook it with `document$.subscribe` |
| Add a home-page section | Emit a `<div class="study-<name>"></div>` from `make_indexes.py` (home branch) and fill it from JS. `foldOut()` in `today.js` gives the same fold-out look |
| Share the login or another API | Add routes in `functions/_middleware.js` after the auth check. `login[0]` is the authenticated user name |
| Move hosting | Any static host can serve `site/`. Only `functions/_middleware.js` (auth and backup) is Cloudflare-specific. Replace it with your host's auth and a small key-value endpoint |

**Constraints to keep in mind**
- `localStorage` belongs to one browser and one origin. A second domain or app won't see it, so share data
  through `/api/backup`.
- `/api/backup` is last-write-wins with no merging. If two clients write, one can overwrite the other.
- Cloudflare Pages rejects files over 25 MiB, and `build.sh` deletes them from the site.
- KV free plan: about 1,000 writes a day, which is why pushes are throttled.
- Steps 1 to 3 of the build rewrite Markdown, so never run them on your only copy of the notes.
- MathJax comes from `cdn.jsdelivr.net`. If the other project blocks third-party scripts, host it yourself.
